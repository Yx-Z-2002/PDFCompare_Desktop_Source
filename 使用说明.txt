PDFCompare 2.3 桌面版 — 使用说明

1. 直接使用
下载 PDFCompare_Desktop_v2_3.exe，Windows 10/11 64 位下双击运行。
这是原生桌面窗口，不需要打开浏览器，也不需要自行安装 Python。
首次启动需将内置运行时解压至当前用户目录，可能需要多等几秒。
程序处理文件时不需要联网。空闲时关闭窗口即可退出；处理时可点“中止任务”，关闭窗口也会先请求中止并等待安全退出。

新增：中止当前任务（2.3）
提取、比较或原文搜索期间，可点击“中止任务”。状态栏随后显示正在中止，任务真正结束后才恢复开始按钮，避免新旧任务同时写结果。
中止是安全停止请求：程序会在读取、逐页提取、整理表格及写出结果的检查点退出；正在进行的单次 PDF 解码或底层表格分析需等待该步骤返回，并非强制杀掉进程。
已完成的旧结果保留；中止的未完成提取目录会清理。若 A/B 提取已经完整完成、随后比较被中止，完整提取文件仍保留，提示中会给出位置。
重新比较时先生成临时结果，成功后才替换旧比较文件；中止不会用半份报告覆盖旧结果。若结果已经保存完毕，中止请求不再撤销这次完成的工作。

新增：字段未提取到的定位提示（2.3）
“字段未提取到”是解析结果，不能解释为“原 PDF 没有字段”。PDF 看起来同一行、同一表格的文字，在文字层中可能分成多段、多个坐标位置。
新版针对无边框同行多组字段、字段名跨多行、值在右侧但字段名换行、前置独立序号增加识别处理，并保留逐页定位证据。
未能确定时仍保留待核对状态，不会从邻近需求或正文提及中随意补值。详情中的诊断会说明已找到的线索，并区分字段解析、字段名差异、页边裁切和文字层问题；具体能否定位取决于该 PDF 提供的文字信息。
如果怀疑裁切误排除字段：先将上下手动裁切设为 0，关闭“按横线识别页眉页脚”和重复页边清理，再重新提取对照。原文搜索不受这些裁切设置限制。

新增：桌面差异红绿标记（2.2）
在“比较结果”中选中条目，详情会直接标出具体改动；“展开全文”窗口也保留颜色。
- 红色：A 中删除的文字或修改前文字。
- 绿色：B 中新增的文字或修改后文字。
- 一般只标记变化片段，未变部分保持普通颜色；特别长且变化密集的区间会整体标记，并提示核对。
- 仅 A / 仅 B 命中的记录按对应红 / 绿显示；这只表示本次提取命中范围的差异。
- 编号重复时需人工核对，不强行逐条配对。
离线 HTML 比较报告也保留颜色；CSV 为纯数据格式，不保存字体颜色。

新增：顶部第一条 / 底部最后一条横线模式（2.2）
勾选“按横线识别页眉页脚”后，使用主界面模式选项选择直接采用首末线或保守识别。
默认选中直接采用首末线，但自动裁切总开关仍默认关闭。
直接模式：在可见页顶搜索区域内，由上到下选择第一条满足长度要求的横线；在页底搜索区域内选择最后一条。顶部线以上为页眉，底部线以下为页脚。
不再要求线外有文字、不再因连接竖线或靠近文字而自动否决，适合已经确认分隔线正确的文件。
这也意味着表格边框可能被选中，启用前请预览；找不到符合位置和长度条件的横线时，该侧不裁切。
如分隔线较短或位置较深，可在“高级设置”调整搜索区域及最小宽度。
切换模式或参数后，需要重新提取才能改变结果。

按横线自动识别页眉页脚
不依赖“页码”“保密”等关键词，也不要求每页文字相同。放在页顶/页底、由独立横线与正文隔开的内容，即使文字像正文也可以按版面位置排除。

操作：
① 在主界面选好 PDF A/B，在页边识别一栏选 A 或 B，点“预览页边识别”。
② 橙色蒙层表示建议排除区域，绿色横线表示识别出的边界。可逐页翻看、缩放，关闭蒙层查看原页，或查看识别依据与排除文字。
③ 确认范围正确后，勾选主界面“按横线识别页眉页脚”，再提取/比较。
注意：看见预览蒙层不等于开关已经开启。窗口会同时显示自动建议和按当前设置实际裁切的 pt 数值。

规则：
- 支持 PDF 中的矢量实线、虚线（包括由独立短线段组成的虚线）及细长填充矩形；扫描图片中的横线暂不直接识别。
- 默认仅搜索页顶、页底各20%范围，横线长度至少占可见页宽55%。可在高级设置调整。
- 保守识别模式会跳过与表格竖线相连/相交、明显属于网格、横穿文字/图像的线；直接首末线模式会按位置采用它们。两种模式都不使用搜索区域外的正文中部横线。
- 同一侧有多条线时，直接模式采用最外侧符合几何条件的线；保守模式采用最外侧通过额外检查的线。
- 每页单独识别，没有满足当前模式条件的横线时不裁切；识别记录包含采用/跳过原因及模式。
- 原始 PDF 不会被改写，排除只影响本次提取范围。
- 这仍是版面规则：如果真正正文也被放在页边横线外，程序无法仅靠几何判断作者意图，务必核对预览。
- 手动裁切与自动结果同时设置时，各侧采用较大的排除范围。

诊断计数：cropped_lines 为实际裁切完全排除的文字行数，repeated_removed_lines 为重复清理移除行数；removed_lines 为两者总和。auto_removed_lines 单独统计自动建议页边区域，不与总数再次相加。

2. 提取与比较
① 选择 PDF A 和 PDF B。
② 填写“查询字段”和“查询内容”，例如 Require Key / XGen。
   B 默认沿用 A 条件；也可取消勾选后独立填写。
③ 点击“提取并比较”，或先“仅提取”，检查后再比较。
④ 在 A/B 结果页查看全部条目、命中条目或待核对条目。
   选中一条即可看到描述、字段原文、页码与识别提示；双击条目或点击“展开全文”可用独立窗口阅读。
   小屏幕完成任务后会自动收起输入区域，可点击展开后再次修改文件与条件。
⑤ 在“比较结果”查看差异，选中条目查看双方文字的红绿标记及未命中原因。
⑥ 可在程序内预览原 PDF，按页跳转及缩放；可导出 CSV 或打开结果目录。
“导出完整表格”导出该侧全部识别记录或全部比较记录，不限于屏幕临时筛选。

3. 当你认为“有内容却没提取到”
先去“诊断与溯源”，选择 A/B，输入编号或关键词，点击“搜索原文文字层”。
这项检索使用独立的 PDF 文字解码器，搜索整份 PDF，不受本次页边裁切或字段筛选影响。
它会列出页码和上下文；编号也可能只是引用，仍应打开原 PDF 核对。
再判断属于哪种情况：
- 已识别但未命中：看字段原文是否满足查询内容。
- 字段未提取到/值为空：程序无法判断条件，不等于原文没有；查看条目详情的诊断与定位证据。
- 未识别编号：核对默认 AT-XXX-数字 格式；特殊编号在高级设置修改正则。
- 无文字层或乱码页：先做 OCR 或重新导出含正确文字层的 PDF。
- 页边被裁切：高级设置将上下裁切恢复为 0，关闭自动裁切后重试。
默认关闭重复页边清理及自动分隔线裁切，减少误删正文风险。

4. 本次实际修复
- 支持全角冒号/横线、字间空格、编号与标题换行及部分无冒号标题。
- 改善字段名称换行、字段名和内容分行、重叠字形造成的识别失败。
- 按实际表格列识别属性，处理序号列和同一行的多个“字段—内容”对。
- 遇到扫描/损坏/清理空白页时停止跨页归属，避免后面的属性串到前一条。
- 增加逐页诊断、字段证据、原文搜索及仅单侧提取命中的原因核查。
- 不再把“提取结果没命中”直接写成“原文缺少该编号”。
- 后台处理与进度提示；PDF 原文渲染和检索共享互斥锁，避免并发冲突。

5. 查询与比较规则
字段查询不区分大小写，容忍字母之间的空格和换行；仍保留选项边界。
例如 XGen 能匹配 X Gen，而不把 XGeneration 当成相同选项。
只有已识别且命中的条目参与比较。两份 PDF 使用不同条件时，差异也可能来自筛选范围。
比较按编号对应，分别比较标题与描述；默认逐字比较，可选择忽略空白排版。
同一编号重复出现会保留全部记录并标为需核对，不擅自挑选一条。
“全部一致”仅说明本次已识别、已命中范围一致，不能证明整份 PDF 完整相同。

6. 保存内容
默认结果位置：当前用户 Documents/PDFCompare，可在“高级设置”修改。
每次运行建立独立时间戳文件夹，不覆盖上一次结果。
A/、B/：matches.csv（命中三列表）、all_items.csv（全部记录）、extraction_report.json（完整证据和诊断）。
comparison/：comparison.csv、differences.csv、issues.csv、summary.json、comparison_audit.json。
另有 settings.json、all_results.zip 和可离线打开的 HTML 报告；HTML 只是附加导出，不是操作界面。
原始 PDF 不被修改，程序退出时清理当前进程的临时副本。
程序日志：%LOCALAPPDATA%\PDFCompareDesktop\data\PDFCompare.log。
启动日志：%LOCALAPPDATA%\PDFCompareDesktop\launcher.log。
启动异常：%LOCALAPPDATA%\PDFCompareDesktop\data\startup_error.txt。

7. 测试样例
examples/Demo_A.pdf、Demo_B.pdf 是人工生成的回归样例，不是你的业务文档。
使用字段 Require Key、查询 XGen：
A 应命中 AT-X-1、AT-X-2、AT-X-3；B 应命中 AT-X-1、AT-X-2、AT-X-5。
结果应为：1 条一致、1 条描述不同、1 条仅 A 命中、1 条仅 B 命中。
AT-X-4 应被筛选排除。

8. 已知限制和验证范围
尚未内置 OCR。纯扫描 PDF、部分扫描混合页、损坏字体映射不能保证自动提取。
复杂双栏/并排需求、特别的跨页表格或自定义编号/状态模板仍需核对诊断。
最新测试结果见 tests/validation_summary.json；包含原功能回归及横线页边识别新增用例。
本次仍未收到实际出现字段漏提的 PDF；修复针对已复现的版面结构，不能据此认定你的特定漏提案例已经解决。请提供问题 PDF、查询字段/内容、漏掉的编号或页码，才能确认具体原因。
Windows exe 的结构、运行时资源及哈希已经验证；桌面流程在 Linux Tk 环境测试。
当前构建环境不能完成 Windows 实机启动验证，仍需在你的 Windows 电脑运行确认。
若仍有问题，请提供一份出现漏提的 PDF、查询字段/内容、漏掉的编号或页码以及日志，便于定点复现。
